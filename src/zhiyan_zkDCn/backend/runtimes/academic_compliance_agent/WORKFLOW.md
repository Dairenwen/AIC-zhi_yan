# Agent 工作流说明

本 Agent 采用简化后的学术合规检测流程：

```text
输入论文
-> 文档解析
-> 加载学术合规规则库
-> 四类合规检测并行执行，并分别调用大模型辅助生成检查结构
-> 风险聚合
-> 汇总四个检查结构，生成学术合规性总结
-> 写入 LangGraph 长期记忆
-> 合规报告输出
```

## 四类并行检测

四类检测在逻辑上相互独立，均依赖文档解析结果和规则库，因此在 LangGraph 中设计为并行分支。每个检查节点都会先执行规则检测，再调用大模型辅助生成该模块的结构化检查结果：

1. 学术论文规范检查
2. 引用与参考文献核验
3. 图表一致性检查
4. 格式与投稿规范检查

每个检查结构包含：

- 模块百分制得分
- 模块优秀点
- 模块风险项
- 模块修改建议
- 模块总结

## 大模型使用位置

大模型用于两个环节：

1. 四个检查节点的大模型辅助检查
2. 汇总四个检查节点的大模型检查结构，生成最终学术合规性总结

风险等级统一使用中文五档：`极高`、`高`、`中`、`低`、`极低`，不再面向用户输出 P0/P1/P2/P3。

最终总结内容包括：

- 学术合规性打分：百分制
- 学术合规性的优秀点
- 学术合规性的修改建议

## 记忆机制

本 Agent 使用 LangGraph 自带记忆能力：

1. 短期记忆：`PostgresSaver` checkpointer
   - 按 `thread_id` 保存同一会话的图状态。
   - 适合连续调试同一篇论文、同一轮检测任务。
2. 长期记忆：`PostgresStore`
   - 按 `user_id` 保存长期用户记忆。
   - 当前保存用户检测画像、最近 10 次检测摘要、上次得分、上次总体风险等级和常见修改建议。

配置 PostgreSQL 后，运行开始时 `intake_node` 会读取长期记忆，报告生成后 `report_node` 会写入长期记忆。

如果 `.env` 中设置：

```env
COMPLIANCE_AGENT_USE_LLM=false
```

系统会关闭大模型调用，使用规则检测和模板报告兜底。

## 输出结果

每次运行会生成两类文件：

```text
output/compliance_agent/*_report.md
output/compliance_agent/*_result.json
```
